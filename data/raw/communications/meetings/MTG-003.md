# Meeting Summary
The team finalized the authentication and authorization architecture for Project Orion. The key decision is the implementation of a "Secure Retrieval Boundary" where authorization filters are applied *before* RRF and reranking. This ensures that the LLM never receives unauthorized content. The system will use metadata filters based on the user's role, department, and classification (per ITSEC-006).

# Decisions Taken
1. **Auth Flow:** Authorization must be enforced as a pre-filter at the retrieval stage (before RRF and Reranking).
2. **Filter Logic:** Use a logical OR for role-based access and specific ownership checks for `confidential` documents.
3. **Cache Security:** Semantic cache keys must include a hash of the authorization context to prevent cross-role data leakage.
4. **Documentation:** The "Secure Retrieval Boundary" must be explicitly documented in ENG-001.

# Open Issues
1. **ChromaDB Filter Performance:** Need to verify if complex boolean filters on metadata lists introduce significant latency.
2. **Ownership Transitions:** How to handle authorization when a document owner leaves the company or changes departments.
